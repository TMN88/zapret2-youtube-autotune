# YouTube Autotune 2 — OpenWrt 24/25

Автоматический поиск **2–3 разных самостоятельных TCP/TLS-стратегий zapret2** через установленный официальный Blockcheck2. Проверяются только ресурсы YouTube; в конце включается первая стратегия, остальные сохраняются отдельно. Если две стратегии подтвердить не удалось, скрипт завершается с ошибкой и возвращает исходную конфигурацию.

## Обязательная ручная подготовка

До запуска:

1. Установите zapret2 вместе с Blockcheck2 и **остановите его службу**.
2. Отключите/исключите YouTube в **podcop / forcop / forkozz / steer** (включая Podkop/Forkop, общие списки с YouTube, ручные домены и FakeIP).
3. Отключите остальные обходы и VPN-перехват YouTube. Запускайте из SSH на самом роутере.

На старте эти требования выводятся белым на красном фоне и ярко-жёлтым. Скрипт не меняет настройки других обходов и не пытается автоматически проверить каждую их возможную конфигурацию. Вы отвечаете за ручную подготовку.

## Одна команда

```sh
wget -O /tmp/youtube-autotune.sh 'https://raw.githubusercontent.com/TMN88/zapret2-youtube-autotune/main/install.sh' && sh /tmp/youtube-autotune.sh
```

Оставьте SSH-сеанс открытым. При закрытии сеанса/прерывании срабатывает откат; подбор нужно запустить заново. Поиск может занять десятки минут. Логи и команда ручного отката выводятся в начале работы.

## Что происходит

1. Одна проверка необходимых условий: OpenWrt 24/25, остановленный `nfqws2`, известная конфигурация, установленный Blockcheck2, доступные команды и WAN-интерфейс. Нет проверки флота, прошивки, VPN, Tailscale, смены DNS или установки пакетов.
2. Создаётся root-only backup `/root/zapret2-youtube-backup-ДАТА-PID`. Сохраняются исходная конфигурация, сгенерированный `config`, собственные старые hostlist/стратегии и состояние автозапуска.
3. В отдельном временном каталоге запускается установленный native `standard` Blockcheck2: `www.youtube.com`, IPv4, TLS 1.3, `SCANLEVEL=force`, три последовательные попытки. Поиск останавливается после восьми успешных проб или по лимиту времени; установленный движок не переписывается. Используются его текущие standard-тесты, а не старый фиксированный набор пилота.
4. Завершённые успешные команды проверяются через native `custom`: **каждый кандидат отдельно на каждой цели** — `www.youtube.com`, превью `i.ytimg.com/vi/jNQXAC9IVRw/hqdefault.jpg`, `youtubei.googleapis.com`, `redirector.googlevideo.com` — по три попытки с **TLS 1.2 и 1.3**. Стратегия должна пройти все цели и оба TLS. Если подтверждённых вариантов мало, выполняется один поиск TLS 1.2 и проверяются только новые команды.
5. Каждый прошедший кандидат отдельно загружается в настоящую службу zapret2 и проверяется через WAN. Страница должна вернуть HTTP 200 и ≥10 КБ, превью — HTTP 200 и ≥1 КБ. Для корней API/CDN допустимы 200/404/405: это проверка ответа сервера, не функциональности API. Между кандидатами служба останавливается. Ошибочные варианты исключаются.
6. Сохраняются максимум три варианта, минимум два. В UCI-сборке создаются `yta_1`, `yta_2`, `yta_3`; активен **только `yta_1`**. В официальной shell-сборке активен первый, остальные параметры сохраняются в отдельных файлах. Старые UCI-стратегии отключаются, но сохраняются в конфигурации и backup; custom hooks выключаются. Конфигурация других обходов не меняется.

Три альтернативы — разные команды, каждая работает сама по себе. Это не три одновременно включённых профиля и не объединение результатов разных доменов. Разные команды могут относиться к одному семейству методов; различие семейств не гарантируется.

## Границы результата

По умолчанию проверяются **IPv4, TCP 443, TLS 1.2/1.3**. QUIC/HTTP3 и IPv6 не подбираются; HTTP3 curl и его архивы не скачиваются. HTTP-ответ API/CDN не доказывает воспроизведение видео, работу всех CDN, 4K или приложение на LAN-устройстве. После подбора проверьте YouTube на клиенте.

Для дополнительной проверки настоящего медиапотока передайте файл с одной свежей HTTPS-ссылкой `*.googlevideo.com/videoplayback?...`, полученной с того же WAN:

```sh
sh /tmp/youtube-autotune.sh --media-url-file /root/youtube-media-url.txt
```

Тогда каждый устанавливаемый кандидат также должен загрузить ≥64 КБ video/audio (HTTP 200/206). Ссылка хранится только во временном root-only curl config; она не выводится в лог и аргументы процесса. Закрытая/просроченная ссылка приводит к отклонению кандидата. Файл ссылки и результаты в `/tmp` следует удалить после работы.

## Совместимость

- **OpenWrt 24.x и 25.x**, независимо от `opkg`/`apk`: пакеты не устанавливаются.
- Архитектура не зашита: используются уже установленные бинарники для вашего роутера.
- Routerich / Zapret Manager с `/etc/config/zapret2`, секцией `main` типа `zapret2` и `init.d/openwrt/uci2config`.
- Официальный `bol-van/zapret2` с shell-файлом `/opt/zapret2/config` и `NFQWS2_OPT`. Неизвестная схема отклоняется до изменений.
- Нужны BusyBox-команды, UCI/ubus/jsonfilter, curl с TLS 1.2/1.3, nftables, setsid, sha256sum и полное установленное дерево Blockcheck2. Обычно они уже входят в используемую сборку. При отсутствии зависимости скрипт останавливается с сообщением; установите её вручную подходящим пакетным менеджером.
- Основной путь `/opt/zapret2`, WAN-сеть `wan`. Есть `--base` и `--wan-network` для другого пути/сети. Служба называется `/etc/init.d/zapret2`.

```sh
sh /tmp/youtube-autotune.sh --check
sh /tmp/youtube-autotune.sh --want 2 --scan-seconds 900
sh /tmp/youtube-autotune.sh --base /opt/zapret2 --wan-network wan
```

`--scan-seconds` — лимит одного запуска Blockcheck2, 10–7200 секунд, по умолчанию 1800. Незавершённые пробы не засчитываются. Режимы старого пилота `--preset`, автоматическая установка zapret2 и скачивание HTTP3 curl удалены. Прежняя команда с `--no-quic` остаётся допустимой.

## Результаты и переключение

- `/etc/zapret2-youtube-autotune/strategy-1.txt` … `strategy-3.txt` — подтверждённые параметры.
- `/etc/zapret2-youtube-autotune/youtube.txt` — ограниченный hostlist YouTube.
- Backup содержит сырые логи Blockcheck2, `dry-run`, проверки службы и копии подтверждённых команд.
- Для UCI можно выбрать одну из `yta_N` в LuCI, выключив остальные `yta_N`. Для официальной shell-конфигурации замените только параметры стратегии внутри `NFQWS2_OPT` на содержимое нужного `strategy-N.txt`, сохранив `--filter-tcp=443 --filter-l7=tls --hostlist=/etc/zapret2-youtube-autotune/youtube.txt`, затем перезапустите службу. Файлы `.txt` — параметры nfqws2, не shell-скрипты.

## Откат

Выполните **точную команду**, напечатанную вашим запуском:

```sh
sh /root/zapret2-youtube-backup-ДАТА-PID/rollback.sh
```

Или `sh /tmp/youtube-autotune.sh --rollback /root/zapret2-youtube-backup-ДАТА-PID`.

При ошибке, HUP, Ctrl+C или TERM конфигурация возвращается автоматически, служба остаётся остановленной — как перед подбором; прежний автозапуск восстанавливается. Отдельный watchdog делает возврат после аварийного завершения родительского процесса. Он не переживает отключение питания/перезагрузку: в таком случае выполните сохранённый `rollback.sh` вручную. При обнаружении параллельных изменений UCI/config автоматическая перезапись останавливается с указанием backup.

Lock исключает два параллельных запуска. После аварии/потери питания сначала проверьте backup и выполните откат. Только убедившись, что подбор и его Blockcheck2 больше не работают, удаляйте старый lock `/var/lock/zapret2-youtube-autotune.lock`. Скрипт не убивает посторонние nfqws2/Blockcheck и не очищает их firewall-таблицы.

## Исходники и проверки

Изучены актуальные на момент изменения исходники:

- [konkere/zapret2-slipstream, 64830c2](https://github.com/konkere/zapret2-slipstream/blob/64830c24ab7f3d01b156b74d22c24d385e5dd0cb/zapret2-slipstream.sh): разделение TLS-прогонов, запасные варианты, остановка процесса и очистка. Здесь лог разбирается строже: обязательны все повторения и все цели; нет исключения провалившегося домена из результата.
- [bol-van/zapret2, ca7ed6a, Blockcheck2](https://github.com/bol-van/zapret2/blob/ca7ed6a9867c27517d8d6f9737cc88c0225cf57d/blockcheck2.sh): native standard/custom, API `pktws_curl_test`, формат попыток, штатная очистка. [Официальный custom runner](https://github.com/bol-van/zapret2/blob/ca7ed6a9867c27517d8d6f9737cc88c0225cf57d/blockcheck2.d/custom/10-list.sh) использует eval, поэтому допускаются только проверенные инертные токены, без shell-конструкций, `--lua-init`, `--new` и сторонних hostlist.

В рантайме используется именно установленная версия движка и её скрипты: автоматического обновления zapret2 нет. Расширенные native-команды с кавычками/выражениями Lua консервативно исключаются из автоприменения.

`python3 scripts/build.py` собирает один самодостаточный `install.sh`; Python на роутере не нужен. `python3 -m unittest discover -s tests -v` проверяет разбор настоящего формата native-логов, три альтернативы, неполные/ложные успехи, инъекции, private hook, UCI-сохранение, конфликты и идемпотентный откат. Это локальные тесты с подставными службой/UCI, **не испытание на реальном роутере/провайдере**. CI выполняет те же адресные проверки.
