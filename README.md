# YouTube Autotune 3 — подбор, резерв и Failover

OpenWrt **24.10 / 25.12**, уже установленный zapret2 и native Blockcheck2. Подбираются до трёх самостоятельных TCP/TLS-стратегий — **по одной из разных семейств**:

1. **TCP Segmentation** (`tcpseg`).
2. **Multisplit / Multidisorder**.
3. **Fake TLS / Seqovl**. Комбинация с fake/seqovl относится к этому семейству, даже если содержит multisplit.

**Одна TCP/TLS-стратегия активна, до двух остаются резервными.** Только прошедшие тесты YouTube варианты сохраняются. Если подтверждены два семейства — будет один резерв и жёлтое уведомление об отсутствии третьего. Меньше двух — ошибка без итогового применения/с откатом. Непроверенные стратегии для заполнения количества не добавляются.

## Обязательная ручная подготовка

Перед запуском:

- zapret2 установлен вместе с Blockcheck2; служба **остановлена**;
- YouTube отключён/исключён в **podcop / forcop / forkozz / steer**, включая Podkop/Forkop, общие списки, ручные домены и FakeIP;
- остальные обходы и VPN-перехват YouTube отключены.

На старте — **белое предупреждение на красном фоне и ярко-жёлтые требования**. Эти настройки скрипт за пользователя не меняет. При повторном запуске собственный Failover приостанавливается на время подбора под общим lock.

## Команда запуска

```sh
wget -O /tmp/youtube-autotune.sh 'https://raw.githubusercontent.com/TMN88/zapret2-youtube-autotune/main/install.sh' && sh /tmp/youtube-autotune.sh
```

Запускайте от root по SSH на роутере. Сеанс оставьте открытым. При прерывании выполняется откат. В начале выводятся путь backup/логов и команда восстановления.

## Цветной результат

В конце выводятся:

- **зелёный:** сколько TCP/TLS-стратегий подтверждено из трёх семейств;
- **голубой:** сколько применено (**1**) и сколько осталось резервных (**0–2**);
- список семейства и состояния каждого варианта: **АКТИВНА / РЕЗЕРВ**;
- отдельная строка QUIC: применена одна проверенная UDP-стратегия либо причина пропуска;
- состояние Failover;
- **жёлтый:** третье семейство не найдено, QUIC не применён, использован кэш;
- **красный:** ошибка и фактическое количество подтверждённых/применённых стратегий; откат отмечается жёлтым.

## Как выбираются стратегии

Используются **установленные** standard/custom-тесты Blockcheck2 и его бинарники, без скачивания и подмены движка. Проверки идут через выбранный WAN; прокси-переменные игнорируются.

1. Однократная проверка совместимости, остановленного zapret2, необходимых команд, свободной RAM (≥32 МБ MemAvailable) и известных конфигураций. Tailscale, прошивка, DNS, настройки других обходов и пакеты не меняются.
2. Backup исходной конфигурации и состояния служб.
3. Поиск TLS 1.3 на `www.youtube.com`: native standard, `SCANLEVEL=force`, по три последовательные попытки. Из каждого семейства собираются до трёх кандидатов, а не три похожих варианта первого успешного метода. Не относящиеся к трём семействам пробы пропускаются. После заполнения трёх групп поиск завершается штатной очисткой.
4. Каждый кандидат проверяется native custom **на всех целях и с обоими TLS 1.2/1.3**, по три попытки: страница YouTube, превью `i.ytimg.com/vi/jNQXAC9IVRw/hqdefault.jpg`, `youtubei.googleapis.com`, `redirector.googlevideo.com`. Успехи разных команд или разных доменов не объединяются. Неполные/неудачные попытки и строки SUMMARY не засчитываются.
5. Если семейств недостаточно, выполняется один поиск TLS 1.2. Уже проверенные команды повторно не гоняются.
6. Кандидаты по очереди загружаются в настоящую службу zapret2. Прошедший вариант проверяется отдельно, без наложения других TCP-стратегий. Из каждого семейства сохраняется первый прошедший вариант.
7. В конце включается первый TCP/TLS-вариант; остальные остаются выключенными резервами. При неудаче выполняется возврат.

Native custom использует eval, поэтому параметры допускаются только в консервативном безопасном формате — без shell-конструкций, произвольного `--lua-init`, `--new` или сторонних hostlist. Расширенные Lua-выражения автоматически не применяются. Фиксированные команды старого пилота не подставляются вместо поиска.

## Сохранение результатов

Подтверждённые стратегии, время и контрольные суммы сохраняются в `/etc/zapret2-youtube-autotune/`. Повторный запуск использует результаты **не старше 24 часов**, если совпадают WAN-интерфейс/адрес/шлюз, OpenWrt, curl, схема конфигурации и контрольные суммы движка/standard-тестов.

Кэш не обновляет свой срок при каждом чтении. Старые/изменённые результаты, другой WAN или обновлённый движок требуют нового подбора. При повторном применении из кэша заново проверяется активная стратегия; резервы не прогоняются целиком без причины. При её неуспехе — откат и рекомендация `--refresh`.

```sh
sh /tmp/youtube-autotune.sh --refresh
```

## QUIC — отдельно и по необходимости

По умолчанию режим **auto**:

- без HTTP3 в установленном curl — QUIC пропускается; curl и архивы не скачиваются;
- если YouTube через прямой QUIC работает — обход QUIC не нужен;
- только после **двух неудачных прямых QUIC-проверок при рабочем TCP** запускается native поиск QUIC;
- кандидат должен пройти Blockcheck2 на странице и превью, затем две проверки HTTP/3 и контроль TCP после применения;
- только после этого добавляется **отдельный UDP/443-профиль**; TCP-стратегия остаётся одна активная;
- при отсутствии рабочего QUIC сохраняется рабочий TCP, выводится `not_found`. Завершение процесса/ошибка движка вызывает общий безопасный откат.

Подтверждённый QUIC из действующего кэша можно повторно использовать после текущих проверок, без нового полного поиска. Failover переключает TCP-стратегии и сохраняет отдельный подтверждённый QUIC-профиль; он не запускает периодические сканирования QUIC.

```sh
sh /tmp/youtube-autotune.sh --no-quic
```

## Автоматический Failover

Устанавливается локальная OpenWrt-служба **`youtube-failover` (procd)**. Она запускается после успешного подбора и при загрузке роутера. Внешних автоматизаций и cron нет.

- Интервал — **60 секунд после предыдущего цикла**. Проверяются страница YouTube (HTTP 200, ≥10 КБ) и превью (HTTP 200, ≥1 КБ), TCP через WAN.
- Для переключения нужны **три последовательных проблемных цикла**. Успешная проверка сбрасывает счётчик.
- Недоступный WAN, ошибка DNS, ошибки сертификата и HTTP 403/429/5xx считаются **неопределённым результатом**: счётчик сбрасывается, переключения нет.
- Резерв проверяется **дважды подряд с паузой**. Только затем он становится активным и сохраняется в конфигурации.
- Если первый резерв не подтверждён — проверяется второй. Если оба не помогают — возвращается исходная стратегия и её состояние службы.
- Между попытками переключения — **15 минут**. Это предотвращает постоянное переключение при общей проблеме сети/YouTube.
- Один общий lock исключает одновременный подбор/переключение. Ручная правка конфигурации или изменение WAN/движка приостанавливают автоматические изменения, а не затираются.
- В обычном цикле состояние пишется в `/tmp`, не во flash. Durable backup создаётся только при подтверждённой проблеме перед изменением конфигурации.

Статус:

```sh
sh /etc/zapret2-youtube-autotune/control.sh --status
```

Показывает номер активной TCP-стратегии и последний результат, например `healthy`, `failure_1`, `switched_1_to_2`, `suspended_config_changed`. При смене контекста заново выполните подбор после ручной подготовки.

Отключить монитор:

```sh
/etc/init.d/youtube-failover stop
/etc/init.d/youtube-failover disable
```

Или установить стратегии без запуска монитора: `sh /tmp/youtube-autotune.sh --no-failover`.

## Совместимость и параметры

- OpenWrt **24.10 / 25.12**, `opkg`/`apk`: пакеты скриптом не устанавливаются.
- Архитектура не зашита: используются установленные бинарники вашего роутера.
- Routerich / Zapret Manager UCI: `/etc/config/zapret2`, секция `main` типа `zapret2`, `init.d/openwrt/uci2config`.
- Официальный shell config: `/opt/zapret2/config` с `NFQWS2_OPT`. Неизвестная схема отклоняется до изменений.
- Нужны UCI/ubus/jsonfilter, curl с TLS 1.2/1.3, nftables, setsid, sha256sum, стандартные BusyBox-команды и полное дерево Blockcheck2.
- Имена службы `/etc/init.d/zapret2`, LAN по текущей конфигурации, WAN по умолчанию `wan`. Неизвестные зависимости устанавливаются вручную.

```sh
sh /tmp/youtube-autotune.sh --check
sh /tmp/youtube-autotune.sh --want 2 --scan-seconds 900
sh /tmp/youtube-autotune.sh --base /opt/zapret2 --wan-network wan
```

`--scan-seconds` — лимит отдельного запуска Blockcheck2 (10–7200, по умолчанию 1800). Засчитываются только завершённые пробы. `--want 2` явно ограничивает результат двумя семействами.

## Файлы и откат

- `strategy-1.txt` … `strategy-3.txt` — подтверждённые параметры. Это аргументы nfqws2, не shell-скрипты.
- `quic.txt` — отдельная подтверждённая UDP-стратегия, если найдена.
- `active` — номер текущей TCP-стратегии; после Failover активной может быть не первая.
- `youtube.txt` — hostlist только YouTube; остальные домены не добавляются.
- В UCI создаются `yta_1` … `yta_3` и необязательный `yta_quic`. Старые стратегии сохраняются выключенными; custom hooks выключаются без удаления файлов. Не редактируйте UCI одновременно с подбором.

Backup: `/root/zapret2-youtube-backup-ДАТА-PID`. Логи Blockcheck2, результаты и исходные конфигурации остаются там. Команда восстановления печатается при запуске:

```sh
sh /root/zapret2-youtube-backup-ДАТА-PID/rollback.sh
```

Откат возвращает конфигурацию, собственные файлы, состояние zapret2 и прежнего монитора. При первом подборе zapret2 исходно остановлен, поэтому после отката тоже остановлен. При неудачном Failover исходная работавшая стратегия запускается обратно.

Ошибка, HUP, Ctrl+C или TERM вызывают откат; отдельный watchdog восстанавливает состояние после аварийного завершения родительского процесса. Он не переживает отключение питания — после перезагрузки используйте сохранённый `rollback.sh`. При обнаружении параллельных изменений автоматическая перезапись останавливается с указанием backup. Посторонние процессы/таблицы Blockcheck2 не очищаются.

## Границы проверки и разработка

Страница/превью и ответы корней API/CDN **не доказывают воспроизведение видео, 4K, все CDN и приложение на LAN**. Для дополнительной проверки реального потока можно передать свежую HTTPS-ссылку `*.googlevideo.com/videoplayback?...`, полученную с того же WAN:

```sh
sh /tmp/youtube-autotune.sh --media-url-file /root/youtube-media-url.txt
```

Тогда при установке кандидат также должен загрузить ≥64 КБ video/audio (HTTP 200/206). URL хранится в root-only временном curl config, не выводится в аргументы процесса/логи. После работы удалите файл URL и временный `media.curl`. Failover делает короткие проверки страницы/превью; он не сохраняет истекающий media URL для постоянного мониторинга. IPv6 не подбирается.

Использованы подходы [Slipstream](https://github.com/konkere/zapret2-slipstream) и API/формат логов [официального Blockcheck2](https://github.com/bol-van/zapret2/blob/master/blockcheck2.sh). Семейства взяты из native [15-misc](https://github.com/bol-van/zapret2/blob/master/blockcheck2.d/standard/15-misc.sh), [20-multi](https://github.com/bol-van/zapret2/blob/master/blockcheck2.d/standard/20-multi.sh), [23-seqovl](https://github.com/bol-van/zapret2/blob/master/blockcheck2.d/standard/23-seqovl.sh), QUIC — [90-quic](https://github.com/bol-van/zapret2/blob/master/blockcheck2.d/standard/90-quic.sh).

`python3 scripts/build.py` собирает самодостаточный `install.sh`; Python на роутере не нужен. Адресные локальные тесты проверяют парсер, семейства, кэш, цветной результат, UCI/QUIC, пороги/ложные срабатывания, переключение и откат. Используются подставные UCI/служба/curl: это **не подтверждение работы на реальном роутере/провайдере и не гарантия сохранения удалённого доступа при OOM/сбое питания**. На реальном роутере требуется отдельная проверка результата.
