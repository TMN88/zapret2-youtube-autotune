# YouTube Autotune 4 — Fast Strategy Scanner

Версия 4.0.4: для `--resume-scan` действует отдельный режим только контрольных проверок — 1 воркер, 1 профиль, минимум 44 МБ MemAvailable перед запуском и остановка ниже резерва 32 МБ. Поиск в этом режиме запрещён. Порог нового поиска остаётся 48 МБ. Расход на конкретном роутере пока не измерен; автоматическая проверка RAM не гарантирует защиту от любого OOM.

Версия 4.0.3 сохраняет кандидатов при остановке поиска по лимиту. Продолжение из такого backup: `sh /tmp/youtube-autotune.sh --resume-scan /root/zapret2-youtube-backup-DATE-PID`. Повторное сканирование пропускается; требуется совпадение исходной конфигурации, а все выбранные кандидаты проходят новые строгие проверки и проверку через службу. Частичный отчёт не является доказательством работоспособности. Если отчёт отсутствует или не прошёл проверку, новый поиск автоматически не запускается.

**Только BlockcheckW. Blockcheck2 полностью исключён, включая резервный путь и контрольные тесты.** Если быстрый движок несовместим или не дал достаточного результата, скрипт заканчивает работу с понятной ошибкой и сохраняет/восстанавливает исходную конфигурацию.

Проект для OpenWrt **24.10.x / 25.12.x**, установленного zapret2 и YouTube. До трёх разных семейств: **TCP Segmentation**, **Multisplit/Multidisorder**, **Fake TLS/Seqovl**. Одна TCP/TLS-стратегия активна, до двух — в резерве. Два подтверждённых семейства дают один резерв и предупреждение; меньше двух — без успешного применения. Изменение `repeats` не создаёт новое семейство.

## Запуск одной командой

```sh
wget -O /tmp/youtube-autotune.sh 'https://raw.githubusercontent.com/TMN88/zapret2-youtube-autotune/main/install.sh' && sh /tmp/youtube-autotune.sh
```

Запускайте от root по SSH. Сеанс оставьте открытым; прерывание вызывает безопасную остановку и откат.

### Обязательная ручная подготовка

1. **zapret2 установлен, служба остановлена.**
2. YouTube исключён из **podcop / forcop / forkozz / steer**, включая Podkop/Forkop, общие списки, ручные домены и FakeIP.
3. Для YouTube отключены другие обходы, VPN-маршрутизация и сторонний перехват.

На старте — белый заголовок на красном фоне и ярко-жёлтые требования. Эти настройки за пользователя скрипт не меняет. Собственный Failover при повторном подборе приостанавливается под общим lock.

## Совместимость и установка движка

- OpenWrt 24.10 / 25.12, musl. ARM64/Filogic, ARM, MIPS/MIPSEL (в том числе MT7621), x86 и другие архитектуры, имеющие официальный подходящий бинарник.
- Нужен **nfqws2 с `--filter-mark`**, согласно upstream — zapret2 ≥1.0.5. Проверяются точная опция и `--dry-run`; установленный zapret2/бинарник не заменяется.
- BlockcheckW v0.12.1 использует `/opt/zapret2`: альтернативный путь для нового сканирования отклоняется без создания системных ссылок и переноса файлов.
- Нужны nftables/NFQUEUE, curl с TLS, **jq**, UCI/ubus/jsonfilter, setsid, sha256sum и обычные BusyBox-команды. Отсутствующая зависимость сообщается до сканирования; при необходимости установите небольшой `jq` через `opkg install jq` / `apk add jq`. Python, Cargo, Docker и компиляция на роутере не используются.
- Для нового поиска нужно **≥48 МБ MemAvailable**; при применении действующего кэша — ≥24 МБ. При 48–64 МБ автоматически выбираются 2 воркера и 4 профиля, RAM проверяется каждую секунду; при падении ниже 32 МБ собственный подбор останавливается. От 64 МБ действует прежний адаптивный режим. Перед каждым процессом память проверяется заново, в том числе после загрузки бинарника. Это ограничения нагрузки, а не гарантия отсутствия OOM: расход на конкретном роутере ещё нужно измерить. Другие службы, включая Tailscale, не останавливаются ради памяти.

Существующий совместимый `blockcheckw` используется без переустановки. Иначе скачивается только архив для нужной архитектуры из **официального GitHub Releases v0.12.1**. SHA256 закреплены в установщике по digest официальных assets. Неверный файл не запускается. MIPS byte order определяется по ELF; неподдерживаемые ABI (например, отсутствующий mips64el) отклоняются.

Бинарник кэшируется в `/usr/libexec/youtube-autotune/`; его отдельная контрольная сумма проверяется перед повторным использованием. Перед сохранением требуется свободное место под бинарник и ещё 2 МБ для журналов/восстановления; запись атомарная. Каталог не включается в каждую транзакционную копию конфигурации, чтобы Failover не записывал мегабайты одинаковых данных во flash. При откате этот неактивный кэш бинарника остаётся, как уже установленная зависимость.

## Быстрый алгоритм

1. **Кэш первым.** Сохранённые результаты не старше 24 часов используются без полного повторного поиска, если совпадают WAN/адрес/шлюз, конфигурация, nfqws2/Lua и бинарник поискового движка. Чтение не продлевает срок. Кэш формата v3 однократно инвалидируется из-за изменения формата доказательств; его файлы сохраняются в backup.
2. **Параллельный `scan`.** Только `www.youtube.com`, TLS 1.3/1.2; без HTTP и других тестовых сайтов. По умолчанию быстрый этап ограничен 90 секундами. Число воркеров выбирается по памяти: **8 / 16 / 32**, ёмкость одного nfqws2 — **16 / 64 / 128 профилей**. CPU, текущая нагрузка и `--workers` могут уменьшить эти значения, вплоть до 4 воркеров при высокой нагрузке. Во время работы проверяется запас памяти; ниже 24 МБ подбор останавливается.
3. **Отбор по семействам.** Точные дубликаты исключаются. До четырёх кандидатов на семейство; native `check --take 1` запускается отдельно для каждой группы. Три быстрых варианта одного метода не выдаются за три семейства.
4. **Строгий JSON.** Проверяются `schema`, `outcome`, domain, embedded-режим, реальные workers/profiles, очередь, таблица, метки и группа процессов. Для принятой строки обязательны `working=true`, **`passes_ok=3`, `passes_total=3`**, наблюдавшиеся байты и непротиворечивая подлинность. Частичный, сломанный, обрезанный без результатов или неизвестный отчёт не становится успехом.
5. **Контроль без обхода.** Успешная прямая контрольная проба главного домена не считается доказательством эффективности стратегии. Если YouTube доступен без обхода, установка не объявляется успешной за счёт формальных «рабочих» строк.
6. **Контрольные цели:** страница `www.youtube.com`, превью `i.ytimg.com/vi/jNQXAC9IVRw/hqdefault.jpg`, `youtubei.googleapis.com`, `redirector.googlevideo.com`. Проверяются оба TLS. Уже подтверждённый TLS 1.3 главной страницы повторно не гоняется. Вспомогательные хосты могут работать напрямую: для них проверяется переносимость стратегии, а не необходимость обхода.
7. **Реальная служба.** Прошедший кандидат отдельно загружается в zapret2 и проверяется через WAN. Это короткая проверка преобразования/применения конфигурации; три полные загрузки уже выполнены поисковым движком. Неуспешный вариант не сохраняется. После проверки всех выбранных вариантов включается только первый.

Общий бюджет **поиска и контрольных прогонов — 600 секунд** по умолчанию. `--scan-seconds` меняет этот общий бюджет, а не даёт каждому проходу отдельные полчаса. Подготовка, скачивание, остановка процессов и применение имеют свои конечные ожидания и не входят в эти 600 секунд. Лимит не превращает незавершённую проверку в успешную.

Без чистого эталонного VPN нельзя доказать абсолютную идентичность ответа. BlockcheckW проверяет полноту канала и доступную ему ось подлинности, HTTPS проверяет сертификат; неподтверждённая абсолютная подлинность отдельно оговаривается. HTTP 200 сам по себе не заменяет три полные загрузки.

Конкретное ускорение **не обещается**: измерения на вашем роутере ещё нужны. Скрипт показывает фактическую длительность подготовки, поиска, контрольных тестов, применения и всей работы.

## Безопасность

- Перед изменениями сохраняются исходные конфигурации, собственные файлы и состояние служб.
- BlockcheckW запускается с `--embedded --no-conflict-cleanup`, собственной nftables-таблицей `yta_bcw_*`, отдельными NFQUEUE и smoke-очередями. Занятый диапазон не используется.
- Временные правила касаются помеченных сокетов сканера. DNS, системные маршруты, sysctl, conntrack и чужие таблицы не перенастраиваются. Проверяется локальный маршрут помеченных проб через выбранный WAN; при несовпадении — остановка.
- Необязательный upstream-запрос ISP к `ipinfo.io` подавляется. Из служебной сети используются получение бинарника и DoH; тестовые ресурсы — только YouTube.
- Никаких `killall`: завершается только собственная группа процессов, удаляется только записанная таблица собственного запуска. Сигналы Ctrl+C/HUP/TERM вызывают очистку/откат; watchdog помогает после аварийного завершения родителя.
- Ручные параллельные изменения конфигурации не перезаписываются автоматически. Роутер не перезагружается.

## QUIC

**BlockcheckW v0.12.1 не поддерживает QUIC. Медленного поиска QUIC в v4 нет.**

- Без HTTP3 в установленном curl проверка пропускается; другой curl не скачивается.
- Если прямой QUIC работает — отдельная стратегия не нужна.
- При двух неудачных прямых пробах можно повторно проверить **ранее сохранённую и защищённую контрольной суммой** QUIC-стратегию: dry-run, две HTTP/3-проверки и контроль TCP через службу. Только после успеха она включается отдельно для UDP/443.
- Если сохранённой стратегии нет/она не прошла проверку, остаётся рабочий TCP; выводится предупреждение `unsupported_by_scanner` / `not_found`. Успех TCP не выдаётся за успех QUIC.
- `--no-quic` отключает эти проверки. Failover сохраняет уже подтверждённый отдельный QUIC-профиль при переключении TCP.

## Failover и результаты

Локальная служба **`youtube-failover` (procd)** сохраняется. Она не запускает сканер при проблемах:

- проверки страницы/превью раз в 60 секунд после предыдущего цикла;
- три последовательных проблемных цикла до попытки переключения;
- две успешных проверки резервной стратегии с паузой;
- минимум 15 минут между попытками;
- DNS/WAN, HTTP 403/429/5xx — неопределённый результат без переключения;
- если резервы не помогают — исходная стратегия восстанавливается;
- общий lock с подбором, backup перед изменениями, автозапуск после перезагрузки;
- ручная правка конфигурации/смена WAN или движка приостанавливает автоматические изменения.

В `/etc/zapret2-youtube-autotune/` остаются `strategy-1.txt` … `strategy-3.txt`, `active`, hostlist, кэш и управляющий скрипт. В UCI — одна активная `yta_N` и выключенные резервы; необязательная `yta_quic` — отдельно. Старые стратегии сохраняются выключенными, custom hooks отключаются без удаления их файлов.

**Цветной итог:** движок, фактическое время, число кандидатов, число подтверждённых семейств, одна активная стратегия, резервы по именам, QUIC, Failover и backup. Зелёный — успех, голубой — информация, жёлтый — предупреждение, красный — ошибка. Непроверенные стратегии для заполнения количества не создаются.

```sh
sh /etc/zapret2-youtube-autotune/control.sh --status
```

## Параметры

```sh
sh /tmp/youtube-autotune.sh --refresh
sh /tmp/youtube-autotune.sh --workers 4 --scan-seconds 300
sh /tmp/youtube-autotune.sh --no-quic --no-failover
sh /tmp/youtube-autotune.sh --check
```

`--check` выполняет короткую локальную проверку без скачивания/сканирования; полная совместимость BlockcheckW проверяется перед новым поиском. `--want 2` ограничивает результат двумя разными семействами. `--wan-network` выбирает WAN. Поисковый движок сейчас требует `/opt/zapret2`.

Необязательная проверка реального видеопотока сохранена:

```sh
sh /tmp/youtube-autotune.sh --media-url-file /root/youtube-media-url.txt
```

Нужна одна свежая HTTPS-ссылка `*.googlevideo.com/videoplayback?...` с того же WAN. При применении проверяется ≥64 КБ video/audio с HTTP 200/206. URL не выводится в аргументы процесса/логи; после работы удалите его файл и временный `media.curl`. Успех страницы, превью или корня API/CDN не доказывает воспроизведение видео, все CDN, 4K и работу приложения на LAN. IPv6 не подбирается.

## Откат

Точная команда выводится в начале запуска:

```sh
sh /root/zapret2-youtube-backup-ДАТА-PID/rollback.sh
```

Или `sh /tmp/youtube-autotune.sh --rollback /root/zapret2-youtube-backup-ДАТА-PID`.

Откат восстанавливает конфигурацию и состояние zapret2/старого монитора. После неудачного первичного подбора zapret2 остаётся остановленным, как до запуска; после неудачного Failover прежняя работавшая стратегия запускается обратно. Кэш скачанного бинарника остаётся неактивным. Watchdog не переживает отключение питания: после перезагрузки используйте сохранённый rollback вручную. Проверка RAM не является гарантией от OOM/потери удалённого доступа.

## Разработка и проверки

`python3 scripts/build.py` собирает самодостаточный `install.sh`. На роутере Python не нужен. `python3 -m unittest discover -s tests -v` использует настоящий jq и подставные UCI/curl/отчёты сканера. Проверяются архитектуры, подпись опции `--filter-mark`, SHA256, повторное использование бинарника, JSON/контрольные пробы, разные семейства, дедупликация, бюджет, кэш, Failover, QUIC, очистка и откат.

Исходники движка: [rcd27/blockcheckw v0.12.1](https://github.com/rcd27/blockcheckw/tree/v0.12.1). Прямо используются его `scan`, `check`, `--take`, embedded-изоляция и JSON-контракт; Rust-механизмы не переписаны. Устаревший последовательный парсер и резервный движок удалены.

Локальные тесты и GitHub CI **не заменяют испытание на реальном OpenWrt**. Реальная скорость, расход памяти и маршрутизация под установленными обходами требуют отдельного теста на устройстве с независимым способом восстановления доступа.
