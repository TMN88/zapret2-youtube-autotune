# YouTube autotune: Podkop + zapret2

Подбор стратегии **на подключении самого роутера** через встроенный `blockcheck2.sh` и установка профилей только для доменов YouTube. Отдельный новый проект; не изменяет репозиторий Zapret Manager.

## Запуск

На роутере от root:

```sh
wget -O /tmp/yt-autotune.sh https://raw.githubusercontent.com/TMN88/zapret2-youtube-autotune/main/install.sh && sh /tmp/yt-autotune.sh
```

Сначала можно выполнить только читающую проверку:

```sh
sh /tmp/yt-autotune.sh --check
```

Быстрая установка TCP-пары с успешного пилота, с обязательной проверкой на текущем роутере и возвратом при ошибке:

```sh
sh /tmp/yt-autotune.sh --preset --no-quic
```

Это **preset**, а не обещание, что стратегия пилота лучшая для любого провайдера. По умолчанию выполняется настоящий подбор. Он может занять десятки минут; не редактируйте в это время конфигурацию через LuCI.

## Требования v1.0

- OpenWrt **24.10**, opkg, **aarch64_cortex-a53**. MIPS не поддерживается этой упаковкой manager/zapret2.
- Podkop с VPN-секцией; по умолчанию `main`. Forkop не заменяется и пока не поддержан.
- UCI-сборка zapret2 от Routerich, используемая Zapret Manager. Если её нет, нужен уже установленный Zapret Manager: скрипт запустит его установку zapret2.
- Работающий VPN для загрузки зависимостей и DoH; обычный WAN для честных тестов. Перехват OUTPUT в Podkop должен быть выключен. Сам скрипт его не переключает.
- Не менее 35 МБ свободного `/tmp` для отдельного HTTP3 curl. При необходимости ставится только зависимость `xz` из настроенных подписанных feeds. Новая прошивка/ядро не устанавливаются.
- Нет несохранённых UCI-правок и посторонних стратегий/custom.d. Они не перезаписываются автоматически. Уже работающий чужой zapret2 лучше оставить на месте; используйте другой пилот.

## Что делает

1. Проверяет совместимость и конфликтующие настройки.
2. Создаёт закрытую копию `/root/zapret2-youtube-backup-ДАТА-ВРЕМЯ-PID` и самостоятельный `rollback.sh`.
3. При необходимости устанавливает zapret2 через установленный manager с выключенной начальной конфигурацией. Системный curl не заменяется: HTTP3 curl загружается в RAM с проверкой фиксированного SHA-256.
4. В выбранной секции заменяет Russia Inside его отдельными составляющими, удаляет `youtube`, сохраняет остальные списки, пользовательские домены, подсети и дополнительные секции. При оставшемся FakeIP прекращает подбор и возвращает состояние — чужие пользовательские правила не удаляет.
5. Запускает **родной Blockcheck2**, `TEST=custom`, `SCANLEVEL=force`, пять последовательных попыток. Сами пробы принудительно идут через WAN; через VPN выполняется только DoH/загрузка файлов.
6. Выбирает общий успешно повторённый вариант для страницы/превью и отдельный вариант для API. Парсер принимает лишь строки из встроенного allowlist; лог не исполняется как shell-код. Среди одинаково прошедших вариантов предпочтены простые без fake-инъекций.
7. Отдельно проверяет HTTP3 с `--http3-only`. Не выдаёт TCP fallback за успех QUIC. Не прошедший QUIC-профиль не устанавливает; `--require-quic` делает его обязательным условием.
8. Проверяет параметры через nfqws2 dry-run, запускает только hostlist-профили TCP/443 и, при подтверждении, UDP/443. После повторных загрузок тел ответов сохраняет UCI и включает автозапуск zapret2.

Стратегии и hostlist хранятся в UCI и `/etc/zapret2-youtube-autotune/`. Прошивка, AWG-профили, Tailscale, его ключи/регистрация, network/firewall не меняются. При ошибке/обычном прерывании выполняется возврат. Непредвиденные параллельные изменения UCI не перезаписываются — скрипт останавливается и печатает путь копии для ручной проверки. Новые пакеты при возврате остаются установленными, но новая служба выключается.

Промежуточные изменения маршрутизации держатся в staged UCI до финальной проверки. Если поддерживаемый Podkop неожиданно сохраняет их при reload, скрипт обнаруживает это и выполняет возврат. Это не защита от произвольной поломки накопителя или принудительного выключения во время установки пакетов.

## Возврат

Путь печатается в начале каждого запуска:

```sh
sh /root/zapret2-youtube-backup-ДАТА-ВРЕМЯ-PID/rollback.sh
```

Либо `sh /tmp/yt-autotune.sh --rollback ПУТЬ_КОПИИ`. Возвращаются исходные Podkop/YouTube и прежнее состояние zapret2. Закрытые копии и журналы не загружайте в публичные issues.

## Дополнительные параметры

```sh
sh /tmp/yt-autotune.sh --section main --wan-network wan
sh /tmp/yt-autotune.sh --curl /tmp/curl-http3
sh /tmp/yt-autotune.sh --require-quic
sh /tmp/yt-autotune.sh --media-url-file /root/media-url.txt
```

Media URL — свежая прямая HTTPS-ссылка на `*.googlevideo.com`, полученная с того же внешнего IP роутера. Скрипт не выводит её подпись, проверяет диапазон до 1 МБ и тип video/audio. Без неё проверяются страница, превью и ответ API endpoint; это **не доказательство воспроизведения видео**. Корень API закономерно может вернуть 404/405: это проверка ответа сервера, а не полноценного API-запроса.

Обязательно проверьте приложение на устройстве за роутером. Список конечный: он не гарантирует все CDN/IP, 4K и длительную нагрузку. IPv6 в этой версии не подбирается.

## Результат пилота

26 октября 2026 на одном совместимом роутере проверены TCP-профили:

```text
Основные домены: --payload=tls_client_hello --lua-desync=multidisorder:pos=1,midsld
API YouTube:    --payload=tls_client_hello --lua-desync=multidisorder:pos=1,host+1,midsld
```

Страница, превью и API прошли повторы; реальный MP4 прошёл 5/5 загрузок, пользователь подтвердил практический результат. При этом QUIC не заработал, а отдельный адрес redirector.googlevideo.com имел проблему TLS1.3 через WAN. Эти ограничения не объявляются устранёнными и не превращаются в универсальный preset для всех провайдеров.

## Разработка и источники

`install.sh` собирается из `src/core.sh`, `src/select.awk` и `data/`; Python на роутере не нужен.

```sh
python3 scripts/build.py
python3 -m unittest discover -s tests -v
sh -n install.sh
```

Перед публикацией тестируются ранжирование, отказы при частичном успехе/неизвестных командах, сохранение дополнительных списков, воспроизводимость сборки и POSIX-синтаксис. Это не замена полному end-to-end испытанию каждого поддерживаемого роутера.
